How to build a client intake form

  1. Create sections first. Click Add section, give it a title (for example “Medical history”), and optionally describe what belongs inside.
  2. Add questions to each section. Inside a section press Add field. Fill in the human-friendly Label (what staff/client sees) and pick the Type (text, checkbox, date, etc.).
  3. Set the field key. The builder auto-fills a key based on the label. Keys must be unique and contain letters/numbers/underscores only; they become JSON keys in saved submissions.
  4. Configure details. Use the options that appear (Required, Placeholder, Choices, Min/Max, etc.) to control validation and default values.
  5. Organise as needed. Use the up/down arrows to reorder sections or questions, and Duplicate/Remove to copy or delete fields.
  6. Save the form. Click Save or Save and continue editing. Re-opening the form will show the saved layout. Use the Form class tab only if you have a custom Django form class that should render/validate the data instead of the dynamic builder.

Working with the JSON editor

  1. Press JSON editor to open the raw configuration. You can copy it for backup or paste a layout from another system.
  2. Edit the JSON carefully, then click Apply. The visual builder refreshes to reflect your changes. Reset restores the JSON to the latest saved builder state.
  3. Always keep the structure: a top-level meta object and a sections array. Each section contains a fields array, with each field defining at least key, label, and type.

Example JSON skeleton:

{
  "meta": { "version": 1 },
  "sections": [
    {
      "title": "Section title",
      "description": "",
      "fields": [
        {
          "key": "unique_key",
          "label": "Question text",
          "type": "text",
          "required": true
        }
      ]
    }
  ]
}

Tip: Increase the Schema version whenever you make breaking changes so you can track which intake submissions were collected with which layout.
